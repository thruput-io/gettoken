Reset here (2026-09-25): this attempt turned into fixing real infrastructure technical debt
instead of continuing the plan's milestones — `agent_build.sh` never actually exercised the
brew path, ran the wrong `dynamic.sh` code branch, and reinstalled its whole toolchain from
scratch on every invocation; `scripts/docker/Dockerfile` existed but was unused and stale;
`colima-shared`'s disk was full, causing OOM/segfault failures unrelated to this repo. Fixed:
`Dockerfile` now sources `constants.env` for `DEBIAN_BUILD_DEPS` and is built once;
`scripts/docker/compose.yml` replaces `agent_build.sh`'s hand-rolled `docker run`/`served.sh`
container+network+volume juggling (removed `scripts/served.sh`, now dead); `docker system
prune -a --volumes -f` reclaimed 26GB.

Local-harness effort abandoned as unreliable (2026-09-25): none of the above ever faithfully
reproduced real CI (`CI=true` never set locally, so `dynamic.sh` took the non-CI branch and
`generate-key.sh` ran on every invocation, which real CI never does at all; `make package`
locally vs `make build` in CI; a baked toolchain image vs a fresh `apt-get install` every real
CI run). A whole session was spent chasing an intermittent `gpg: no valid OpenPGP data found`
failure inside that harness that most likely cannot occur in real CI, since real CI's
`ARCHIVE_SIGNING_KEY` is a persisted secret, never generated. Decision: real CI (a real PR) is
the only thing that gets to say "verified" for either platform; `macos-vm` stays only as a fast,
non-authoritative sanity check while writing brew code, never as proof of passing.

M2 completed for real (2026-09-25): `scripts/brew-formulae.sh` (new) generates one formula per
apt package from `packaging.sh`'s resolved `debian/control`/`.install` files — `url`/`sha256`
point at a locally-built tarball (`file://`, D10), `depends_on` parsed straight from each
package's real `Depends` line, `def install` uses Homebrew's own `lib`/`share` accessors
(`brew link` auto-symlinks these into the shared prefix, the standard way, replacing an earlier
draft that hand-rolled `HOMEBREW_PREFIX` symlinks). `src/tools/gettoken/bin/gettoken` resolves
`PATH`/`EXCHANGER_DIR`/`CONTRACTS_DIR` via `$(brew --prefix)` when `brew` is present (matches
`contract.go`'s pre-existing `CONTRACTS_DIR` override, so no Go changes needed) and `SECRET_DIR`
via `$HOME/.gettoken/secrets` on brew (per-user, since there's no separate privileged account in
a normal brew install, unlike apt's root-owned `/var/lib/gettoken/secrets`).
`scripts/deliver-brew.sh` rewritten to mirror `deliver-deb.sh` exactly (copy `src/`, run
`packaging.sh`, copy `Formula/` out) — the placeholder body and `gettoken.rb.todo` are gone.
Fixed a real bug found along the way: `packaging.sh` resolved `dirname "$0"` *after* its own
`cd "$source"`, so `brew-formulae.sh` was never found when invoked from elsewhere.

Verified end to end (`scripts/deliver-brew.sh` run directly, same as `package.sh` invokes it):
