## 2026-09-25 — correction: gettoken's brew prefix detection reverted

The earlier entry's change to `src/tools/gettoken/bin/gettoken` — resolving
`PATH`/`EXCHANGER_DIR`/`CONTRACTS_DIR` via `$(brew --prefix)` at runtime and defaulting
`SECRET_DIR` to `$HOME/.gettoken/secrets` on brew — is reverted to `main`'s version at the
human's request ("yes restore"). It detected the platform at runtime although `PACKAGE_FORMATS`
fixes it at build time, and moving secrets into the calling user's home was a security-model
decision the agent took without putting it to the human. How a brew install locates its
directories, and where secrets live on macOS, is an open question for this plan's decision
register before any replacement is written. No test, README or generator depended on the
reverted behaviour (`git grep` for `brew --prefix`, `.gettoken/secrets`, `HOMEBREW_PREFIX`).

## 2026-09-26 — attempt abandoned per ADR 31

The human abandoned this attempt: "abondon the branch make work in new plan, bring adr", then
"Change #56 As abonded per ADR 31".

**What was attempted.** M1 (version/tag automation) and M2 (22 generated Homebrew formulae
sharing apt's dependency graph) were implemented and verified locally, as recorded above. M3
(tap repository and publishing) and M4 (macOS CI job) were never started. Real CI never ran.

**Why it stopped.** Not a technical failure — the direction changed. ADR 31
(`docs/adrs/0031-apt-and-brew-separate-repos.md`, landing on `main` with the new plan) moves
distribution out of gettoken into the organization's distribution repositories,
`thruput-io/apt` and `thruput-io/brew`, with GitHub Actions there that are not specific to
gettoken. The human then chose Google Artifact Registry to serve apt ("Artifact Registry it
is") and asked that architectures be handled outside code repositories: "I do not want to
bother about amd arm and stuff in my code repos, can't a generic packagin job do that". This
plan builds packages, formulae and publishing inside gettoken, so it no longer fits.

**What the next attempt does differently.** A new plan, started from `main`, owns the problem:
gettoken carries code only, and a generic packaging job in the distribution repositories
builds per architecture, validates and publishes — apt to Artifact Registry (including the GCP
resources), brew to the `thruput-io/brew` tap. Nothing from this branch is carried forward
except ADR 31.
